# 4.5.0 acceptance

Development repair. Official publication remains held.

## Reported failure

Mutual Checker failed intermittently and sometimes reported HTTP 404.

## Reproduction (installed 4.3.9, main Chrome profile, 2026-11-27)

- Signed out: both lookups returned HTTP 404. The check entered the native
  fallback and reported that the signed-in account had changed.
- Signed in: both lookups still returned HTTP 404; the list route returned
  JSON. Started from the home page, the check stopped at once with "Open
  @account's profile". Started on the account's profile, the native dialog
  fallback read 83 of 83 followers and 83 of 84 following in 34 seconds and
  correctly stayed partial.
- The list route, read directly for the same account, returned 83 followers
  and 84 following with no further pages.

## Root cause

Both identity lookups are retired for every session. Without a numeric ID the
engine could never reach the working list route. Success therefore depended on
where the check started: it worked slowly from the subject's open profile, and
failed elsewhere. Signed-out tabs produced the same 404 pages and were
misdescribed. Hypotheses about later-stage 404s, pagination and mis-bound IDs
were checked against the live routes and not observed.

## Repair

For the signed-in account's own check, the ID is bound only when Instagram's
rendered viewer record (username and ID), its rendered app identity and the
visible navigation account all agree, and the binding is re-verified between
and after the two lists. Totals come only from the exact open profile header;
otherwise results stay partial with a prompt to rerun from the profile. Other
accounts keep the native-profile path. A tab with no signed-in account is
reported as such. Identity checks, partial labels, Stop, cooldowns and saved
comparisons are unchanged.

## Unsend restored to 4.3.9

DM Unsend, reaction cleanup and Ghost Mode are restored to the exact 4.3.9 code,
the last version with a verified live removal. The 4.3.10 discovery-recovery
change is withdrawn. Every inbox, DM, reaction and
Ghost source file matches 4.3.9; the generated userscript differs from 4.3.9
only in its version header and the Mutual Checker repair.

## DM Unsend ownership

Reported: Unsend scrolled up three or more times before removing anything.
Check conversation on a designated thread reported that no message was
identified as the user's. Every sent lane computed `justify-content:
flow-end` and every received lane `flow-start`, matching Instagram's own
"message from <name>" labels; the check accepted only flex-end /
flex-start. The shared ownership check now treats flow-end / end and
flow-start / start the same way. Read-only on the live thread, it matched
Instagram's labels on all seven messages; the previous check matched none.
