# 4.3.6 acceptance

Development candidate. Final assembly, source, package safety, production browser,
sandbox, background, rendering and all eight exact-candidate CI checks passed.
Installation was verified, but full authenticated acceptance did not pass. No official
release is recorded. Authorized maintainer dispatch and
release review access are currently unavailable, so official publication
remains on hold.

## Scope

Live diagnosis of 4.3.5 found that a music/audio descendant link was interpreted
as a second post ID. This caused the post-Like activity to skip an otherwise
eligible article. The repair matches full canonical `/p/<id>`, `/reel/<id>`
and `/reels/<id>` paths, keeping query strings and fragments separate from path
identity. Canonical aliases with the same ID remain one target.

Audio-only articles and descendant routes cannot establish a post target.
Different canonical IDs remain ambiguous, and duplicate Like controls still
prevent selection. Same-origin checks, exact root/control revalidation, account
binding, reviewed activity authority and verified outcomes remain unchanged.

Saved Growth seed drafts can also fail to restore when Instagram finishes
verifying the signed-in account after startup. The repair retries read-only
restoration once through the existing context observer, bound to the initial
route, exact account and the draft's fresh Following basis/digest. Edits, new
work, busy state, route changes or evidence drift cancel it. Restoration never
reads seed lists, starts Follow or restores action approval automatically.

## Installed observations and remaining failure

Activation showed 4.3.6 with one userscript host and no sidecar. A One session
test selected only post Likes with the existing goal of ten. Cancel caused no
action. The confirmed run verified three music-backed post Likes and ended
after exhausting loaded eligible activity at three of ten; it did not prove
the ten-action limit. Each native control changed from Like to Unlike, and
one Like persisted on a fresh post page.

The full exported history retained all 90 earlier records plus five new run
records, for 95 total. No actual user history loss or cross-account write was
observed. A later cold profile mount initially lacked verified account identity.
After the page's navigation clearly identified the current account, the panel
still showed Verify account and disabled its activity log controls. No Start
or Clear action was used on that failing mount.

Three synthetic regressions reproduced risks in one-shot history hydration
and writes addressed through the current, changeable account: replacing prior
history or writing one account's events into another scope. These are
source-level conditional failures, not observed loss of the retained live
history. The repair is tracked in [4.3.7 acceptance](./4.3.7.md).

A separate Growth journey used a fresh own-Following basis and three selected
seeds. Normal cold navigation restored the saved selections, profile links and
Read current seed control after account verification became available. No
seed read or Follow started automatically. This is an installed-build pass for
draft restoration, not for reading the seeds or finding candidates.

The next explicit Read current seed attempt opened a native Followers dialog
whose initial heading was still empty. The app backdrop hid its account rail
from accessibility, and the read stopped before ordinary typed-dialog account
validation became available. The draft remained available; no Follow ran.
Later native markup contained the loaded heading and rows, but that did not
turn the already-stopped attempt into a completed seed read. A bounded,
read-only native-opening repair is also tracked in 4.3.7.

The [4.3.5 record](./4.3.5.md) preserves its automated and selected live
observations. Its read-only Insights JSON/text exports matched 18 loaded
carousel observations, and a diagnostics export reported 4.3.5 without the
sampled private identifiers. Its configured up-to-30-minute run expired naturally after
six verified story activities, but no post Like was verified. Its primary
comparison reached the read deadline and retained partial recovery without
completing both lists. Normal Growth navigation exposed the delayed-account
draft restoration failure. None of those observations validates the new build.
Private identifiers, messages, captures and exports remain outside the
repository.
