# 4.3.2 acceptance

## Status

Development candidate. Authenticated tool acceptance and required CI for the
final source are incomplete. Earlier candidate test results do not establish
acceptance for this version. No official 4.3.2 release is recorded here.

## Regressions under review

Home can contain the signed-in account alongside unrelated story and feed
avatars. Presence previously treated all those avatar links as account evidence
and rejected the resulting ambiguity. The userscript now uses the shared
navigation verifier; missing, conflicting or restricted account evidence still
prevents action authority.

Account IDs returned as unsafe JavaScript numbers are rejected before list
requests, including when loaded profile counters are available. Exact numeric
strings retain their full identity.

The search resolver can fall back to the existing allowlisted profile GET route
only after an HTTP 404 or 410. It requires the exact normalized username and
consistent numeric identity. Authentication, challenge, rate-limit and
cancellation guards remain active. The new candidate has not yet established
that this fallback succeeds against the live service.

Manual list capture now reports incremental progress, exposes a dedicated Stop
control and retains captured rows after cancellation. A native backdrop may
hide the profile counters from accessibility while the list is open; those
counters qualify only with exact profile ownership. A fresh ending count is
required before a list can become complete. Missing, stale or conflicting
counts leave the capture partial.

Live like me retains selected activities, duration and optional breaks. Verified
progress remains separate from attempts, skips and uncertain outcomes when
Pause or Stop settles. Growth checkpoints retain a dispatched target until its
result can be reconciled.

Ghost Mode confirmation identifies every selected thread alongside available
native participant labels. The shared review renders the full supported inbox
selection without changing its thread-bound approval. Authenticated removal
acceptance remains pending.

The Pages channel gate permits only the held 4.3.1 web package. Later versions
retain their CI web build and checks without deployment.

Current profile counter controls and profile-prefixed post links have synthetic
native-shaped fixtures. Fixture success does not establish authenticated list
completeness, server-side changes or a one-to-one reconstruction of Instagram.

## Existing evidence and limits

Read-only checks of the preceding candidate confirmed userscript activation
after Chrome's separate user-script permission was enabled. Exported list and
comparison data were independently checked against captured sets; partial
flags remained present. These observations do not establish acceptance of the
new 4.3.2 code or any authenticated mutation.

Focused source regressions cover navigation identity, exact resolver fallback,
manual scan progress/cancellation and owner-bound final counts. Combined
assembly, the complete source suite, rendered fixtures and exact-candidate CI
remain pending for 4.3.2. Earlier CI successes are reference evidence only.
