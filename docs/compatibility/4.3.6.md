# Insta Toolbox 4.3.6 compatibility

This development candidate preserves userscript identity, grants, storage and
the stable update URL. Final source, package, browser, sandbox and rendering
and background checks, all eight candidate CI checks and activation passed.
Three post Likes were verified, including persistence after fresh navigation.
Cold navigation also restored a three-seed read-only Growth draft. Its next
explicit seed read stopped while the newly opened Followers dialog still had
an empty heading, so seed-reading acceptance remains incomplete.
Full authenticated acceptance remains incomplete: cold-start account
verification can leave Presence history controls unavailable, and synthetic
account-transition regressions expose conditional history-scope write risks.
The observed 95-record history stayed intact. See [4.3.7](./4.3.7.md).
Official publication also requires unavailable maintainer dispatch
and release review access.

| Tool | Scope | Boundary |
| --- | --- | --- |
| Live like me post Likes | Full canonical post and reel paths | Music/audio descendants do not identify a post. Conflicting canonical IDs and duplicate Like controls remain ineligible. |
| Native Mutual Checker | Existing lookup routes and exact profile-list reads | Native provenance, readiness, Stop, fresh totals and saved-pair safeguards remain required. |
| Growth | Explicit native seed reads and expiring drafts | Installed cold-navigation draft restoration passed. A separate unlabelled-dialog startup failure prevented the next seed read; no seed read or action approval is automatic. |
| Insights | Loaded-post summaries and exports | Samples are not full account history; missing fields remain unknown. |
| DM and Ghost Mode | Reviewed own-message and own-reaction scopes | Exact account/thread binding, current authority and verified outcomes remain required. |

The canonical matching repair preserves query/fragment handling through the
URL parser. It does not expand support to profile-prefixed permalink paths.
The Growth retry uses the existing context observer and cannot restore a live
review or grant action authority. Both code changes passed independent review;
selected installed outcomes passed, while the remaining native-read, history
recovery and action checks remain incomplete.
Existing activities still need a loaded tab, current account evidence and
verified outcomes; sleep, tab discard and restrictions can interrupt work.

Chrome 138 and newer require **Allow User Scripts**, separately from the
script's enabled switch. Managed workers require userscript-manager APIs and
Web Locks.

Extension, desktop and web/PWA downloads remain on hold at 4.3.1. Consult
[acceptance](../acceptance/4.3.6.md) before publication.
