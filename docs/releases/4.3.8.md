# Insta Toolbox 4.3.8

Development preparation for a same-account multi-tab history repair. A cached
second tab can overwrite the first tab's new session events even when their
sessions run serially. The defect is inherited; the 4.3.7 account-scope repair
did not introduce it. No actual user history loss was observed, and the
preserved real history remains intact.

The approved design stores independent private history changes and confirms
them only after acknowledged writes. The loaded view may lag other tabs.
Clear also excludes older or concurrent activity waiting to sync when it is
later discovered; tabs can record new activity after observing the clear.
The private legacy backup is retained and cannot re-import cleared activity.
Display and export stay limited to 500 entries; bounded cleanup is not a
global physical-storage cap. History implementation and async UI passed
independent review and 85 combined component checks, including the actual
two-panel/session 101-record retention case.

The bounded native skeleton handoff repair passed review and 209 focused
checks after an installed 4.3.7 Growth read stopped before rows. Routine
history status is readable without duplicate live announcements.
